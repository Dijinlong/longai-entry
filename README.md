## 1. 定位：它是什么，不是什么

**是**：一个**同一模型多家挂价**的 API 平台。卖家把自己手里闲置的大模型额度挂出来、自主定价；买家用一个密钥调用，按卖家报价付费。平台负责撮合、调度、结算与故障切换。

**不是**：

- **不是单一上游的转发服务。** 同一个模型通常有多条货源，价格与可用性各自独立，一条出问题不影响另外几条。
- **不是「包月套餐」。** 没有订阅、没有最低消费、没有预存门槛，用多少扣多少。
- **不是模型厂商。** 平台不自研模型，也不修改上游模型的行为；能力边界与官方一致。
- **不是免费额度池。** 所有调用按实付价计费，报价来自卖家挂单而非补贴。

一句话概括差异：**传统中转站的「折扣」是平台定的一个数；这里的折扣是每个卖家各自挂出来的、可比价的、实时变动的多个数。**

## 2. 运作机制

```
卖家挂单（自主定价）
   ↓
上架前逐模型校验（协议能不能通、计费单位对不对）
   ↓
买家请求进入 → 按健康分 + 折扣 + 可用性选择货源
   ↓
单个货源故障 → 熔断并切换，不把错误直接抛给调用方
   ↓
调用流水落库（余额、逐次消费、命中货源都可查）
   ↓
卖家侧结算与提现
```

几个容易误解的点，说清楚：

- **定价权在卖家。** 平台给规则边界（见第 6 节），不给具体价。
- **同一模型的不同协议入口是分开计价的。** 一个模型可能有 OpenAI 兼容、Anthropic 原生、Gemini 原生三条入口，报价条目数因此大于模型数。
- **调度看的是货源的实际表现**，不是卖家自己声明的参数。
- **切换是请求级的**，因此单次调用的耗时里可能包含重试；对延迟敏感的用法应该看状态页的实际观测，而不是只看标价。

## 3. 接入方式

三条入口，同一个密钥（`sk-` 前缀，在控制台的密钥页获取）：

| 协议 | base_url | 典型调用 |
|---|---|---|
| OpenAI 兼容 | `https://ai.dijinlong.com/v1` | `/v1/chat/completions`、`/v1/embeddings` |
| Anthropic / Claude | `https://ai.dijinlong.com` | `/v1/messages`（Claude Code 直接把它当 API 端点） |
| Gemini | `https://ai.dijinlong.com/v1beta` | `/v1beta/models/<model>:generateContent` |

最小可用示例（OpenAI 兼容）：

```bash
curl https://ai.dijinlong.com/v1/chat/completions \
  -H "Authorization: Bearer sk-你的Key" \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek-v4.1-flash", "messages": [{"role": "user", "content": "你好"}]}'
```

改一个 `base_url`、换一个 `model`，其余代码不动 —— 这是它作为「兼容层」的核心承诺。
错误体的字段结构也按各家官方规范对齐（不是所有中转站都做到这一点）。

## 4. 价格是怎么算出来的

这是全篇最该看的一节。比价出问题，九成不是算错数，是**口径没对齐**。

### 4.1 计费单位不统一，也不能统一

| 类别 | 单位 | 说明 |
|---|---|---|
| 文本 / 向量 / 重排序 | 元 / 百万 tokens | 输入与输出分别计价，通常输出是输入的 3–5 倍 |
| 图像 | 元 / 张 | 有分辨率档位的按档位价 |
| 视频 | 元 / 秒 | 有分辨率、时长档位的按档位价 |

把图像或视频折算成「元/百万 tokens」来排名，是这个行业最常见的错误。**任何跨模态的统一排名都不可信，包括别人的，也包括本页的。**

### 4.2 汇率

官方价以美元计价，页面按**当日公示的汇率**折成人民币后再比较（数值看价格页顶部，本条目不写死）。汇率变动会让「折扣没变、价格变了」，所以引用一个价格，必须同时引用它的更新时刻。

### 4.3 「本站价」的定义

```
本站价 = 官方价 × (1 − 卖家报价的便宜比例)，取当前最深一档
```

「最深一档」意味着它代表**当前能拿到的最好价格**，不是所有货源的平均价，也不是承诺价——货源变化时它会变。

### 4.4 折数换算（最容易读反的地方）

数据源里如果给的是 `percent_off`（便宜了百分之几），换算关系：

```
折数 = (100 − percent_off) / 10
percent_off = 50  →  5 折（付一半）
percent_off = 90  →  1 折（付一成）
percent_off = 99  →  0.1 折
```

`percent_off` 是 0 表示原价，是 100 表示免费。**把 90 读成「九折」而不是「一折」，方向就完全反了**——这个错误在人工报表里出现过，所以这里单独写一遍。

### 4.5 阶梯价与图片 token 折算

长上下文的阶梯价、以及「一张图折算多少 token」这两类，平台不在价格表里做统一折算。需要精确成本时，按你自己的上下文长度分布加权另建表。

## 5. 三个计数口径（务必分清）

同一个平台上，这三个数经常被混用成「在售模型数」，其实是三件事：

| 口径 | 在哪看实时值 | 含义 |
|---|---|---|
| **价目表模型** | [/model-docs](https://ai.dijinlong.com/model-docs) | 有模型档案的型号总数，含当前未上架的。单页会标注「暂无报价」 |
| **在架模型** | [/model-plaza](https://ai.dijinlong.com/model-plaza) | 按模型名去重后，当前真的有货源挂着的 |
| **可算实付价** | [/pricing](https://ai.dijinlong.com/pricing) | 同时有官方价和卖家报价，能直接给出折扣与实付价 |

三者的关系是 **价目表 ⊇ 在架 ⊇ 可算实付价**（历史快照 2026-11-01：352 / 189 / 175）。所以「我们有 N 个模型」这句话单独说是含糊的——准确说法是「**X 个模型档案、Y 个在架、Z 个可比价**」。档案覆盖的厂商数也不等于这些厂商当前都有货。

## 6. 平台规则

- **卖家报价上限 = 官方价的 50%**（即最浅 5 折）；**下限可到官方价的 0.01 折**——这两个是平台规则的边界值，不是当前市场上的实际价位。实际最深的一档看价格页（2026-11-01 快照为 0.1 折）。
- **平台抽成 0%**，属于限时卖家扶持政策，公示截至 **2026-12-31**。之后若调整会先公示。
- **结算货币人民币**，预充值、按量扣费；余额与逐次调用流水在控制台可查。
- **发票与提现**在控制台对应页面发起，规则见 [常见问题](https://ai.dijinlong.com/faq)。
- 定价准入按模型类别执行白名单与自动录入，未通过校验的型号不会出现在价目表里。

## 8. 谁适合用 / 谁不适合

**适合**：需要在多家之间比价、想把成本压到官方价以下的调用方；一个项目里同时用到 OpenAI、Claude、Gemini 三套格式、不想维护三个供应商的；按量付费、不想被套餐绑住的。

**不适合**：需要**唯一固定供应商**、要求上游出具合同与 SLA 链路的合规场景；对首字延迟极度敏感、不接受任何重试的实时交互；以及需要「免费额度」的探索性用法——这里所有调用都计费。
